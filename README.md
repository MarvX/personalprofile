# سایت احسان — نسخه اولیه متصل به حساب کاربری

داشبورد شخصی فارسی و راست‌چین برای مدیریت زندگی روزمره. فایل‌ها در GitHub نگهداری می‌شوند و نسخه‌ی سایت از طریق Vercel منتشر می‌شود.

## اجرا
- پروژه استاتیک است و فعلاً به build command نیاز ندارد.
- آدرس مخزن: https://github.com/MarvX/personalprofile
- برای تست PWA، سایت باید روی HTTPS منتشر شود.

## راه‌اندازی انجام‌شده
- Supabase پروژه‌ی مستقل `ehsan-personal` برای سایت شخصی (جدا از ERP دفتر).
- ورود و ثبت‌نام ایمیلی با Supabase Auth.
- حساب جدید به‌صورت پیش‌فرض `pending` است و تا تأیید مدیر به داده‌ها دسترسی ندارد.
- پروفایل عمومی حساب‌ها در جدول `profiles`؛ اطلاعات خصوصی در `user_records`.
- سیاست‌های RLS برای محدودکردن ردیف‌های هر کاربر به مالک همان ردیف و حساب تأییدشده.
- ذخیره‌سازی ابری وضعیت فعلی داشبورد و همگام‌سازی بین دستگاه‌ها پس از تأیید حساب.
- Vercel environment variables برای آدرس Supabase و کلید عمومی ثبت شده‌اند.
- کلید service-role یا کلید محرمانه در کد مرورگر استفاده نشده است.

## تنظیم آدرس تأیید ایمیل
در Supabase Dashboard → Authentication → URL Configuration، مقدار **Site URL** را روی `https://personalprofile-ruddy-kappa.vercel.app` بگذار و همین آدرس را به فهرست **Redirect URLs** اضافه کن. ثبت‌نام، آدرس فعلی سایت را برای بازگشت پس از تأیید ایمیل می‌فرستد.

## وضعیت مدیر
برای جلوگیری از تصاحب حساب مدیر توسط اولین ثبت‌نام‌کننده، هیچ حسابی خودکار مدیر نمی‌شود. پس از ثبت‌نام صاحب سایت، باید همان حساب یک‌بار از سمت مدیر دیتابیس به `role='admin'` و `account_status='approved'` ارتقا داده شود. بعد از آن، مدیر می‌تواند وضعیت کاربران را از بخش «مدیریت کاربران» تغییر دهد. مدیر فقط فراداده‌ی حساب‌ها و وضعیت تأیید را می‌بیند؛ سیاست‌های RLS دسترسی به محتوای خصوصی کاربران را محدود می‌کند.

## قابلیت‌های فعلی داشبورد
- داشبورد «امروز من»، تم روشن/تاریک و چیدمان واکنش‌گرا
- وظایف، عادت‌ها، هدف‌ها و شمارنده‌های مطالعه/واژگان
- خروجی JSON محلی
- صفحات اولیه‌ی ورزش، مالی، دانشگاه/معماری، زبان، پارتنر و هوش مصنوعی (بعضی از این صفحات هنوز نمایشی هستند)
- PWA با service worker و manifest

## محدودیت‌ها و گام‌های بعد
- فعلاً کل وضعیت داشبورد به‌صورت یک سند ابری per-user ذخیره می‌شود؛ جداول تخصصی و فرم‌های کامل هر ماژول باید در مراحل بعد ساخته شوند.
- صفحه‌ی پارتنر، چت/تماس زنده، اعلان پوش، هوش مصنوعی واقعی، گزارش مالی/ورزشی کامل، تقویم واقعی و مرور G5 هنوز پیاده‌سازی نشده‌اند.
- کلید عمومی Supabase در مرورگر قرار می‌گیرد که برای این منظور طراحی شده؛ امنیت واقعی از Auth و RLS می‌آید.
- پیش از استفاده‌ی جدی، تست ثبت‌نام/ورود/تأیید مدیر و ذخیره‌سازی ابری روی سایت منتشرشده باید انجام شود.
- وظایف و هدف‌های اولیه‌ی نمونه هستند و داده‌ی واقعی کاربر محسوب نمی‌شوند.
